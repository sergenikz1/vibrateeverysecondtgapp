# mail-audit — выгрузка и разбор рабочей почты Mail.ru

Инструмент, чтобы понять, **из чего на самом деле состоит поток писем в компании**:
кто пишет, о чём, как быстро вы отвечаете, что висит без ответа и какая доля
работы — механическая, то есть автоматизируемая.

К приложению из этого репозитория отношения не имеет — отдельная утилита,
лежит в своей папке.

## Пайплайн целиком

```
   ①  БРАУЗЕР                  ②  ЛОКАЛЬНО                 ③  LLM (опционально)
┌────────────────────┐     ┌──────────────────────┐     ┌────────────────────────┐
│ e.mail.ru + консоль│     │ analyze.py           │     │ classify_llm.py        │
│ mailru-export.js   │ ──▶ │ статистика, метрики, │ ──▶ │ таксономия процессов,  │
│                    │     │ отчёт, CSV           │     │ оценка автоматизации   │
└────────────────────┘     └──────────────────────┘     └────────────────────────┘
      .ndjson                 report.html + csv              processes.md
```

Шаг ① обязателен. Шаг ② даёт объективные цифры без единого внешнего запроса.
Шаг ③ — интерпретация: что за процессы стоят за письмами (письма уходят в Claude API,
см. предупреждение ниже).

## ① Выгрузка из браузера

1. Откройте <https://e.mail.ru>, залогиньтесь.
2. **Кликните по любой папке** — так в память страницы попадает CSRF-токен, который
   скрипт подхватит автоматически.
3. Откройте DevTools (`F12`) → вкладка **Console**.
4. Вставьте целиком содержимое `browser/mailru-export.js`, нажмите Enter.
5. Выполните:

```js
await MailAudit.run()
```

Скрипт обойдёт все папки, соберёт письма и по окончании сам скачает
`mailru-export-<дата>.ndjson`. Большой ящик занимает несколько минут — вкладку
не закрывайте.

### Полезные команды

```js
await MailAudit.diagnose()          // что найдено: токен, ящик, список папок
MailAudit.setToken('abc123…')       // задать токен вручную, если не нашёлся
await MailAudit.run({ folders: [0] })            // только «Входящие»
await MailAudit.run({ withBodies: true, bodyLimit: 500 })  // + тела 500 писем
await MailAudit.stats()             // сколько уже выгружено
MailAudit.stop()                    // мягко прервать
await MailAudit.download()          // перескачать то, что уже в базе
await MailAudit.reset()             // стереть локальную базу
```

### Что важно знать

- **Ничего не отправляется наружу.** Скрипт ходит только на `e.mail.ru` вашими же
  cookie и сохраняет файл на диск.
- **Прогресс переживает перезагрузку** — письма пишутся в IndexedDB, повторный
  `run()` дотягивает недостающее, а не начинает с нуля.
- **Тела писем по умолчанию не тянутся**: это один HTTP-запрос на письмо. Для анализа
  структуры потока хватает темы + сниппета. Включайте `withBodies` точечно.
- **Если токен не нашёлся** — DevTools → Network → любой запрос к `/api/v1/` →
  параметр `token` в URL → `MailAudit.setToken('…')`.
- Mail.ru периодически меняет внутренний API. Если выгрузка падает,
  начните с `await MailAudit.diagnose()` — он покажет, на чём именно.

### Формат выгрузки

NDJSON, одно письмо на строку. Первая строка — метаданные (`_meta: true`).

```json
{"id":"1:16871…","thread_id":"…","folder_id":0,"folder_name":"Входящие",
 "date":"2026-03-14T09:12:44.000Z","subject":"Счёт №4471","snippet":"Добрый день…",
 "from":{"name":"Бухгалтерия","email":"buh@postavshik.ru"},
 "to":[{"name":"","email":"me@company.ru"}],"cc":[],
 "has_attachments":true,"attachments":[{"name":"счёт.pdf","size":48210,"type":"application/pdf"}],
 "flags":{"read":true,"flagged":false,"draft":false,"answered":true},"body_text":null}
```

## ② Локальный анализ

Зависимостей нет, только Python 3.8+.

```bash
cd mail-audit/analyze
python3 analyze.py ~/Downloads/mailru-export-*.ndjson --out ./out
```

Свои адреса определяются автоматически по папке «Отправленные»; если не вышло —
задайте явно:

```bash
python3 analyze.py export.ndjson --me me@company.ru,sales@company.ru --out ./out
python3 analyze.py export.ndjson --stale-days 5 --out ./out   # порог «без ответа»
```

### Что появится в `./out`

| Файл | Что внутри |
|---|---|
| `report.html` | Главный отчёт с графиками — открыть в браузере |
| `report.md` | То же текстом, удобно вставлять в задачи/презентации |
| `counterparties.csv` | По каждому контрагенту: объём, скорость ответа, робот/человек |
| `recurring.csv` | Повторяющиеся темы — кандидаты на шаблон или бота |
| `unanswered.csv` | Входящие без ответа: фактический список долгов |
| `threads.csv` | Цепочки: длина, длительность, кто с кем |
| `senders.csv`, `domains.csv` | Топ отправителей и доменов |
| `monthly.csv` | Помесячная динамика входящих/исходящих |
| `messages.csv` | Плоская таблица всех писем — для Excel/BI |

### Что считается

- **Направление** письма (входящее/исходящее) — по папке и по адресу отправителя.
- **Время ответа** — для каждого входящего ищется ближайшее исходящее в той же
  цепочке; отсюда медиана и 90-й перцентиль.
- **Бэклог** — входящие, на которые ответа так и не было, старше `--stale-days`.
- **Рассылки и роботы** — по маске адреса (`noreply@`, `billing@`, …) и по нулевой
  доле ответов при заметном объёме. Считаются отдельно, чтобы не портить статистику
  живого общения.
- **Повторяющиеся темы** — тема нормализуется (снимаются `Re:`/`Fwd:`, номера
  и даты заменяются плейсхолдерами), одинаковые группируются.
- **Нагрузка вне рабочего времени** — до 8:00, после 20:00 и в выходные.

Спам и корзина из аналитики исключаются, но в `messages.csv` попадают.

## ③ Разбор по бизнес-процессам (Claude)

> ⚠️ На этом шаге темы и сниппеты писем отправляются в Claude API. Если в ящике
> есть данные, которые нельзя передавать вовне, — сначала отфильтруйте выгрузку
> или пропустите шаг: отчёт из ② самодостаточен.

```bash
pip install anthropic
export ANTHROPIC_API_KEY=sk-ant-…

python3 classify_llm.py ~/Downloads/mailru-export-*.ndjson --out ./out
```

Работает в три захода (можно по отдельности через `--step`):

1. **discover** — на случайной выборке тем модель выводит таксономию процессов
   именно вашей компании (`taxonomy.json`). Никаких зашитых категорий.
2. **classify** — все входящие прогоняются пачками; на каждое письмо: процесс,
   намерение, срочность, степень автоматизируемости, нужно ли решение человека
   (`classified.ndjson`).
3. **report** — сводка `processes.md`: какой процесс сколько потока съедает
   и сколько из этого механическая работа.

```bash
python3 classify_llm.py export.ndjson --out ./out --step discover
python3 classify_llm.py export.ndjson --out ./out --step classify --limit 2000
python3 classify_llm.py export.ndjson --out ./out --step report
```

Полезные флаги: `--batch-size 40` (писем в запросе), `--workers 4` (параллельность),
`--limit N` (обработать только первые N), `--all-messages` (не только входящие).

Прогон устойчив к обрывам: результаты пишутся построчно, повторный запуск
дообрабатывает остаток. Таксономия кэшируется на стороне API (prompt caching),
поэтому большая часть входных токенов после первой пачки идёт по цене чтения кэша.

## Как этим пользоваться по делу

Порядок вопросов, на которые отчёт отвечает:

1. **Сколько на самом деле писем?** `report.html`, блок KPI. Если 40% входящих —
   рассылки, первая же оптимизация: правило в почте, а не найм.
2. **Кто генерирует нагрузку?** `counterparties.csv`, сортировка по `incoming`.
   Обычно топ-10 адресов дают половину потока — для них имеет смысл отдельный
   канал (чат, форма, тикет-система), а не почта.
3. **Что повторяется?** `recurring.csv`. Тема, встречающаяся 30 раз, — это
   30 раз выполненная вручную одинаковая работа.
4. **Где вы медленные?** Медиана и p90 времени ответа, плюс `unanswered.csv`.
5. **Что вообще можно убрать из людей?** `processes.md` из шага ③ — доля потока
   с `automatable: full/partial` по каждому процессу.
6. **Почему цепочки длинные?** `threads.csv`: цепочка на 12 писем почти всегда
   значит, что в первом письме не хватало данных — лечится формой или чек-листом.

## Ограничения

- Скрипт выгрузки завязан на внутренний API веб-клиента Mail.ru — он не документирован
  и может измениться. Диагностика (`MailAudit.diagnose()`) покажет, что именно сломалось.
- Определение направления письма опирается на названия папок (`Отправленные`/`Sent`);
  для нестандартных ящиков используйте `--me`.
- Эвристика «робот/человек» неизбежно ошибается на пограничных адресах вида
  `info@` — проверьте флаг `automated` в `counterparties.csv`, прежде чем строить
  на нём выводы.
- Время ответа считается по цепочкам; если в компании отвечают из другого ящика
  или по телефону, метрика занижена.
